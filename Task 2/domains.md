# Домены и потоки данных

| Домен | Граница ответственности | Основные данные и продукты данных |
| --- | --- | --- |
| Головной офис | Управление компанией и едиными показателями | KPI, организационная структура, справочники, агрегированные показатели деятельности | 
| Клиники | Операционная деятельность клиник | Разрешенные для аналитики данные о клиентах, персонале, услугах и инвентаризации | 
| Банк (финтех) | Банковские и финансовые операции | Финансовая история, счета, кредиты, платежи, кредитные и операционные показатели | 
| ИИ-сервисы | Модели и сервисы искусственного интеллекта |Медицинские данные используются только в разрешенном ИИ-контуре | 
| Будущие партнеры | Обмен данными с фармацевтическими компаниями и производителем электроники | Продукты данных партнеров, сведения об оборудовании и поставках по согласованным контрактам | 

Легаси-системы не являются самостоятельным бизнес-доменом. SQL Server 2008, PowerBuilder и Apache Camel рассматриваются как временный источник данных и подключаются через адаптеры. По мере миграции ответственность за данные переходит соответствующим доменам.

# Преимущества для бизнеса

## Ускорение вывода продуктов

Новый финтех-сервис или партнер реализует собственный API и event-контракты. Подключение выполняется через стандартный пайплайн, а не через добавление новой бизнес-логики в общий DWH.

## Независимое развитие направлений

Клиники, Банк и ИИ-сервисы владеют своими моделями и продуктами данных. Команды могут менять внутренние системы, сохраняя внешний контракт для потребителей.

## Снижение зависимости от DWH

DWH остается временным источником для легаси-данных. Бизнес-логика переносится в домены, а аналитические преобразования выполняются в пайплайне и продуктах данных.

## Быстрая отчетность

Портал обращается к подготовленным продуктам данных через семантический слой. Запросы отчетности могут масштабироваться независимо.

## Безопасность медицинских и финансовых данных

Медицинский контур отделен от аналитического, а финансовые данные выдаются только в рамках роли пользователя.
